# 安装部署手册

适用版本：doc-qa-service v0.1.0
面向对象：实施工程师 / 客户 IT
预计耗时：15 分钟（标准环境）

---

## 1. 环境要求

| 项目 | 最低配置 | 说明 |
|---|---|---|
| CPU | 4 核 | 解析与向量化是 CPU 密集 |
| 内存 | 8G | PostgreSQL 建议分配 1G 以上 |
| 磁盘 | 50G | 镜像约 1.2G，文档按实际量预留 |
| 操作系统 | CentOS 7+ / Ubuntu 20.04+ | 内核 3.10 以上 |
| Docker | 20.10+ | 需支持 compose v2 |
| 网络 | 内网可访问即可 | 全离线部署无需外网 |
| 端口 | 80 | 可改，见 4.2 |

**部署前自检**（在目标机器执行）：

```bash
docker --version && docker compose version
free -h && df -h /
ss -lntp | grep ':80 ' || echo "80 端口空闲"
```

四项全部通过再往下走。任一项不满足，先解决，不要跳步。

---

## 2. 获取安装包

### 2.1 有外网

```bash
git clone <仓库地址> doc-qa-service
cd doc-qa-service
```

### 2.2 无外网（离线包）

在联网机器上打包：

```bash
docker compose build
docker save -o images.tar doc-qa-service-app doc-qa-service-worker \
  pgvector/pgvector:pg16 nginx:1.27-alpine
tar czf doc-qa-offline.tar.gz images.tar doc-qa-service/
```

拷到目标机器后：

```bash
tar xzf doc-qa-offline.tar.gz
docker load -i images.tar
cd doc-qa-service
```

> 离线包体积约 1.2G。U 盘注意文件系统格式：FAT32 不支持单文件超过 4G，exFAT 或 NTFS 无限制。如果只有 FAT32，用 `split -b 3G images.tar images.part.` 分卷。

## 3. 配置

```bash
cp .env.example .env
```

**必须修改的两项：**

```ini
JWT_SECRET=<32 位以上随机串，可用 openssl rand -hex 32 生成>
POSTGRES_PASSWORD=<数据库密码>
```

**按需修改：**

```ini
EMBEDDING_PROVIDER=mock          # 没有模型服务时保持 mock，仅联调
LLM_PROVIDER=mock
OPENAI_BASE_URL=http://your-llm:8000/v1   # 接入本地 vLLM / Ollama
OPENAI_API_KEY=sk-xxx
ANSWER_THRESHOLD=0.15            # 换真实模型后必须重新标定
```

> 改了 `EMBEDDING_DIM` 或换了 embedding 模型，必须清空已有向量：`docker compose down -v` 后重新上传文档。维度不一致会直接报错。

**网络受限时必须加的一项：**

```ini
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
```

构建镜像时容器要 `pip install`，直连 pypi.org 在国内经常 SSL 中断或超时，表现为
`ReadTimeoutError` 或 `SSLError: UNEXPECTED_EOF_WHILE_READING`。换成国内源即可。
内网环境换成自建的 pypi 镜像地址，完全没有外网时必须走第 2.2 节的离线打包方式。

## 4. 部署

### 4.1 一键部署

```bash
./scripts/deploy.sh
```

脚本依次执行：构建镜像 → 启动数据库并等待就绪 → 启动应用与 worker → 启动 nginx → 轮询 `/healthz`。
失败时会打印容器状态和最近 50 行日志并返回非 0。

### 4.2 修改端口

编辑 `docker-compose.yml` 中 nginx 的端口映射：

```yaml
ports:
  - "8080:80"
```

然后重新 `docker compose up -d nginx`。

## 5. 验证

按顺序执行，每一步都要通过。

**5.1 容器状态**

```bash
docker compose ps
```

四个服务（db / app / worker / nginx）应为 `running`，db 与 app 显示 `healthy`。

**5.2 探针**

```bash
curl -s http://localhost/healthz     # {"status":"ok"}
curl -s http://localhost/readyz      # {"status":"ready"}
```

**5.3 接口文档**

浏览器打开 `http://<服务器IP>/docs`，能看到接口列表。

**5.4 全链路**

```bash
# 注册
TOKEN=$(curl -s -X POST http://localhost/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"test@example.com","password":"12345678"}' | grep -o '"access_token":"[^"]*' | cut -d'"' -f4)

# 上传样例文档
curl -s -X POST http://localhost/api/v1/documents \
  -H "Authorization: Bearer $TOKEN" \
  -F 'file=@samples/员工手册.md'

# 等 5 秒，确认状态为 ready
curl -s "http://localhost/api/v1/documents" -H "Authorization: Bearer $TOKEN"

# 提问
curl -s -X POST http://localhost/api/v1/qa/ask \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"question":"年假有几天？"}'
```

预期：返回 `"refused": false`，`citations` 里有《员工手册.md》，答案含"5 天"。

**5.5 质量基线（可选）**

```bash
python scripts/eval_qa.py --base-url http://localhost
```

返回码 0 表示编造率低于 10%。

## 6. 安装失败怎么办

| 现象 | 去这里 |
|---|---|
| 容器起不来 / 反复重启 | 《故障排查手册》F01、F02 |
| 502 Bad Gateway | F03 |
| 上传报 413 | F04 |
| 文档一直是 pending | F05 |
| 一直拒答 | F08 |
| 磁盘满 | F09 |
